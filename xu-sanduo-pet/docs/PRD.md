# PRD：像素许三多桌面宠物（Coding Companion）

| 字段 | 内容 |
|------|------|
| 产品名称 | 许三多 · 编码桌宠（Xu Sanduo Coding Pet） |
| 版本 | v0.1.0（MVP） |
| 平台 | macOS 12+、Windows 10/11 |
| 形态 | 常驻系统托盘 + 透明置顶桌面精灵 |
| 目标用户 | 本地使用 IDE / 编辑器写代码的开发者 |
| 核心口号 | **不抛弃，不放弃** —— 陪你敲到最后一个 bug |

---

## 1. 背景与目标

### 1.1 问题

写代码时长时间盯屏、久坐、卡壳、深夜爆肝，缺少轻量、有情感陪伴且不打扰心流的反馈。市面上桌宠多为通用萌宠，缺乏「军人式自律 + 编码场景」的人格化陪伴。

### 1.2 产品目标

1. **感知编码状态**：在本地监听用户是否在 coding 工具中工作、是否活跃/空闲。
2. **人格化反馈**：用像素许三多的标志性动作（睡觉、跑步、绕单杠、唱军歌等）映射编码情境。
3. **跨平台**：同一套代码在 Mac / Windows 可安装运行。
4. **低打扰**：透明悬浮、可拖拽、可隐藏；默认不抢焦点、不弹窗轰炸。

### 1.3 非目标（v0.1）

- 不做云同步、账号体系、社交排行。
- 不读取用户代码内容、不上传键鼠原文。
- 不做完整 RPG / 养成数值游戏（可留扩展点）。
- 不强制系统级全局键盘 hook（隐私敏感；MVP 用「前台应用 + 空闲时间」推断）。

## 2. 用户故事

1. 作为开发者，我打开 Cursor/VS Code 开始敲代码，桌面上的许三多进入「认真站岗写代码」状态。
2. 我卡住思考超过几分钟，许三多开始「绕单杠」，提醒我换个思路也是战斗。
3. 我离开电脑去开会，许三多「睡觉」；回来时他「敬礼」欢迎。
4. 我连续 coding 过久，他「跑五公里」，暗示该活动一下。
5. 我提交成功 / 测试通过（从窗口标题等弱信号推断），他「唱军歌」庆祝。
6. 我右键托盘可暂停监听、置顶开关、手动切状态、退出。

## 3. 核心概念

### 3.1 角色设定

- **形象**：像素风新兵，迷彩/草绿作训服、短寸头、朴实笑容。
- **性格**：踏实、执着、「不抛弃不放弃」。
- **台词风格**：短句军旅口语，克制、励志，不油腻。

### 3.2 状态机（MVP）

| 状态 ID | 中文名 | 触发条件（优先级从高到低） | 动画 / 行为 | 气泡文案示例 |
|---------|--------|---------------------------|-------------|--------------|
| `celebrate` | 唱军歌 | 检测到 commit / build success / test pass 等弱信号；或手动触发；持续 8–12s | 原地踏步 + 张嘴唱 | 「不抛弃！不放弃！」 |
| `greet` | 敬礼 | 从 idle/sleep 回到活跃 coding；持续 3s | 举手敬礼 | 「报告！三多归队！」 |
| `coding` | 站岗写码 | 前台为 coding 工具且近期有活动 | 敲键盘循环 | 「任务进行中。」 |
| `monkey_bar` | 绕单杠 | 前台为 coding 工具，但 90s–5min 无键鼠活动（卡壳思考） | 单杠翻转 | 「再想想……」 |
| `running` | 跑五公里 | 连续 coding 活跃时长 ≥ 设定阈值（默认 50min） | 跑步位移 | 「该活动活动了！」 |
| `sleeping` | 睡觉 | 系统空闲 ≥ 5min，或非工作时段长时间无活动 | 躺下打呼 | 「……呼噜」 |
| `idle` | 稍息 | 默认兜底；前台非 coding 工具但系统未空闲 | 站立轻微晃动 | — |
| `debug` | 挠头排查 | 前台窗口标题含 error/fail/exception/debug 等 | 挠头踱步 | 「有情况！」 |

状态切换规则：

- 单一当前状态；进入新状态前可播放 200–400ms 过渡（淡入/转身）。
- `celebrate` / `greet` / `running` 为**有时限的覆盖态**，结束后回落到 `coding` 或 `idle`。
- 用户可在菜单中「锁定状态」用于演示。

### 3.3 编码工具识别（可配置）

默认进程/应用名关键词（大小写不敏感）：

- 编辑器：`Code`, `Cursor`, `Windsurf`, `Trae`, `Zed`, `Sublime Text`, `Atom`, `Notepad++`
- JetBrains：`idea`, `pycharm`, `webstorm`, `goland`, `clion`, `rider`, `phpstorm`, `rubymine`, `datagrip`
- 终端：`iTerm`, `Terminal`, `Warp`, `Alacritty`, `WindowsTerminal`, `wt`, `Hyper`, `kitty`
- 其他：`GitHub Desktop`, `Sourcetree`, `Fork`, `Docker Desktop`

窗口标题弱信号（庆祝/调试）：

- 庆祝：`passed`, `success`, `✓`, `CI green`, `committed`, `push`
- 调试：`error`, `failed`, `exception`, `traceback`, `debugger`, `breakpoint`

## 4. 功能需求

### 4.1 P0（MVP 必须）

| ID | 需求 | 说明 |
|----|------|------|
| F1 | 透明置顶宠物窗 | 无边框、透明背景、alwaysOnTop、可拖拽；点击穿透可开关 |
| F2 | 像素精灵渲染 | Canvas 绘制 32×32（放大 3–4x）帧动画，至少 8 套状态 |
| F3 | 活动监听 | 轮询前台应用 + 系统空闲时间（Electron `powerMonitor` + 平台适配器） |
| F4 | 状态机调度 | 按 §3.2 规则自动切换，1s 节拍评估 |
| F5 | 系统托盘 | 显示/隐藏、置顶、点击穿透、暂停监听、手动状态、关于、退出 |
| F6 | 气泡台词 | 状态切换时短暂显示像素风对话框 |
| F7 | 跨平台打包 | electron-builder 产出 `.dmg` / `.exe`（或 portable） |
| F8 | 本地配置 | `settings.json`：空闲阈值、跑步提醒间隔、缩放、是否开机启动（预留） |

### 4.2 P1（紧随）

- 自定义 coding 应用白名单
- 更细的「今日站岗时长」统计面板
- 右键宠物本体快捷菜单
- 简易音效开关（军歌短音 / 呼噜）

### 4.3 P2（远期）

- VS Code / Cursor 扩展推送真实事件（保存、测试结果、Git）
- 多屏吸附、沿屏幕边缘巡逻
- 皮肤包、季节装

## 5. 技术方案

### 5.1 选型

| 层 | 选择 | 理由 |
|----|------|------|
| 壳 | Electron 33+ | Mac/Win 一套代码；透明窗、托盘成熟 |
| UI | 原生 HTML/CSS + Canvas | 轻量，像素缩放用 `image-rendering: pixelated` |
| 监听 | `powerMonitor` + 平台脚本/模块 | 避免强制安装全局键盘 hook；隐私友好 |
| 打包 | electron-builder | 官方推荐，支持 dmg / nsis |
| 语言 | JavaScript（CommonJS/ESM 混用清晰分层） | 快速落地 MVP |

### 5.2 架构

```
xu-sanduo-pet/
├── docs/PRD.md
├── electron/          # 主进程：窗口、托盘、IPC、监听调度
├── src/
│   ├── monitor/       # 活动信号采集与归一化
│   ├── pet/           # 状态机、精灵帧、台词
│   └── ui/            # 渲染页、气泡、样式
├── assets/
└── package.json
```

数据流：

```
Monitor (每 1s)
  → ActivitySnapshot { app, title, idleMs, isCodingApp, signals }
  → StateMachine.evaluate()
  → PetState
  → IPC → Renderer 播放对应动画 + 气泡
```

### 5.3 平台适配

| 能力 | macOS | Windows |
|------|-------|---------|
| 前台应用 | `osascript` / `active-win` 类方案；无权限时降级为「仅空闲时间」 | PowerShell `Get-Process` + 前台窗口 API 封装 |
| 空闲时间 | Electron `powerMonitor.getSystemIdleTime()` | 同左 |
| 透明窗 | `transparent: true`, `vibrancy` 不用 | 同左；注意 DWM |
| 托盘图标 | Template PNG | 彩色 ICO/PNG |
| 权限说明 | 若启用辅助功能增强监听，在 README 引导 | 一般无需额外权限（MVP） |

**降级策略**：无法读取前台应用时，仅用空闲时间驱动 `sleeping` / `idle` / 定时 `running`，并在托盘提示「增强监听未启用」。

### 5.4 隐私

- 仅本地处理进程名与窗口标题关键词匹配，不落盘原文日志（debug 模式除外）。
- 不采集击键内容、不截屏、不上网（除检查更新预留）。
- 开源可读，配置文件明文本地。

## 6. 交互与视觉

### 6.1 布局

- 宠物默认贴屏幕右下角上方约 80px。
- 精灵显示尺寸：约 96×96 ~ 128×128 CSS 像素。
- 气泡在精灵上方，最多 2 行，自动消失。

### 6.2 动效预算

每个状态 ≥ 2 帧；跑步 / 单杠 ≥ 4 帧；帧间隔 120–200ms。

### 6.3 无障碍与可控

- 全部功能可在托盘完成，不依赖全局快捷键。
- 「隐身模式」：隐藏精灵但保留托盘。

---

## 7. 成功指标（定性 MVP）

- Mac / Windows 均可启动，托盘可见，精灵可拖拽。
- 打开 VS Code/Cursor 敲代码 → 进入 `coding`；离开 5min → `sleeping`。
- 手动菜单可触发全部标志性动作并正确播放。
- 关闭点击穿透后可拖拽；开启后鼠标可点穿到下方应用。
